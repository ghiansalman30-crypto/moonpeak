What is moonpeak?

Four tools that usually live in four repos.

◐

App framework

One file per tool, one folder per View. React hooks for tool data, theme, display modes, state and host actions.

◑

Inspector

ChatGPT-style and Claude-style hosts on localhost. Switch theme, device and display mode. Edit tool data live.

◒

Testing framework

Schema, View and simulation checks in about a second. Playwright fixtures for e2e. Multi-model tool-choice evals.

◓

CLI

new, dev, build, start, inspect, test. Hot reload for both your Views and your server code.

MCP App framework · ChatGPT Apps · Claude connectors

Write it once. It renders in every host.

moonpeak is built on the official MCP Apps SDK, so your Views speak the same protocol ChatGPT and Claude speak. No host-specific forks, no rewrites when a new client adds MCP Apps support.

  • Folders are the config: tools, Views and fixtures are discovered.
  • Return a plain object from a tool and it becomes structured content.
  • Each View builds to a single inlined HTML file, ready for strict CSPs.
  • ChatGPT and Claude extras live behind moonpeak/chatgpt and moonpeak/claude, with safe fallbacks.
my-app/
├─ src/
│  ├─ tools/
│  │  └─ show-moon.ts        # one MCP tool
│  └─ resources/
│     └─ moon/
│        ├─ moon.tsx         # its View
│        └─ moon.css
└─ tests/
   ├─ simulations/
   │  └─ show-moon.json     # fixtures
   ├─ e2e/moon.spec.ts
   └─ evals/moon.eval.json
import { useToolData, useTheme, useCallTool } from "moonpeak";

export const resource = { title: "Moon phase" };

export default function Moon() {
  const { output, isPending } = useToolData();
  const theme = useTheme();
  const callTool = useCallTool();

  if (isPending) return <Skeleton />;
  return (
    <Card theme={theme}>
      <h1>{output.phase}</h1>
      <button onClick={() => callTool("show-moon", next)}>
        Next week
      </button>
    </Card>
  );
}

MCP testing framework

Test MCP Apps in CI. No accounts, no keys.

Simulations are JSON fixtures: tool input, optional mocked output, expectations and host settings. moonpeak test runs them in-process against your real handlers, checks every tool schema and builds every View to make sure it renders.

Need more? --e2e drives the inspector with Playwright, --eval asks real models whether they pick the right tool, and --server points all of it at any MCP server, in any language.

What is an MCP App?

An MCP tool that comes with a UI. The tool declares a ui:// resource, the host fetches that HTML and renders it in a sandboxed frame next to the conversation, and the two talk over a small postMessage protocol. ChatGPT, Claude, VS Code and Goose all support it.

Do I need a ChatGPT or Claude account to develop?

No. The inspector replicates both hosts locally, including theme, display modes and the bridge calls a View can make. You only need a host account when you want to try the deployed app there.

Can I test a server that isn't built with moonpeak?

Yes. moonpeak inspect --server and moonpeak test --server work with any MCP server over Streamable HTTP, written in any language.

Does it work with ChatGPT's Apps SDK?

Yes. Resources carry both the MCP Apps metadata and the older openai/* keys, and moonpeak/chatgpt exposes widget state, file upload and modals when your View runs inside ChatGPT.

What do evals need?

Provider keys (ANTHROPIC_API_KEY, OPENAI_API_KEY) and the matching SDK in your project. Everything else runs offline.

How do I deploy?

moonpeak build then moonpeak start, or import createHandler from moonpeak/server and mount it on any runtime that speaks Fetch.

Yes. MIT licensed, no account, no telemetry.
